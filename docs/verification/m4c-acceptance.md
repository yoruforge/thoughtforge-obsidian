# M4-c 枝の切り出しの検証記録

2026年11月26日、独立 worktree で作成したビルドを macOS の Obsidian 1.15.1 に配置した。専用のプロファイルと Vault を使い、再起動試験では Obsidian プロセスを終了してから同じ Vault を開き直した。

## 自動検証

`pnpm verify` で型検査・ESLint・Vitest（21ファイル、136テスト）・本番ビルドが成功した。Core の変換10ケースには複数 H1、タブ・スペース・順序付きリスト、保護ブロック、CRLF、末尾改行、パス拒否が含まれる。

| 障害注入 | 確認した結果 |
|---|---|
| R1・R2 | 別名で作成した保存先を再起動後に再利用。変更後も元枝を識別できれば再開し、同一内容の兄弟を区別できない場合は停止した。 |
| R3・R4 | 記録の永続化失敗時は作成0件。作成結果が不明な記録では明示確認を要求した。作成済み保存先の欠落、変更、未保存編集では元枝が残った。 |
| R5 | 元置換直後に保存先を失う場合、元が置換後の全文なら復元した。元にも外部追記があれば追記と復旧用原文が残った。 |
| B1・B2 | 改行だけ異なる保存先の再利用を拒否。参照先を確認できないケースでは新規作成前に停止した。 |
| H1・H2 | Undo は枝を復元して新ノートを保持。保存先が変化した Redo は履歴を消費せず、元の外部編集も保全した。 |
| C1 | 既存ノートや大小文字衝突を上書きせず、同時に開始した2要求による作成は1回だった。 |

再実行には `pnpm exec vitest run tests/core/extractBranch.test.ts tests/sync/branchExtraction.test.ts` を使用する。

## 隔離 Obsidian の操作と観測

| ケース | 操作と合格条件 |
|---|---|
| M4C_01 | ポップオーバーで見出し枝を切り出した。コードブロックと子孫を含む新ノート、ブロック ID を保持した元ノートを全文照合し、リンク遷移と「戻る」を確認した。 |
| M4C_02 | タスク枝をコマンドから切り出した。元のタスク記号・字下げ・ブロック ID と、新ノートの本文・子リストを確認した。 |
| M4C_03 | 新規ノート作成後に元の書き込みを失敗させた。元の Markdown 全文が一致し、復旧画面と永続記録を確認した。 |
| M4C_04 | 別内容の既存ノートを指定すると実行ボタンが無効になり、そのノートの内容を保持した。 |
| M4C_05 | Undo 後の元ノートは抽出前の全文と一致し、切り出し先が残った。 |
| M4C_06 | 再起動後、2本目の「メモ」に対して記録済みのフォルダと別名が表示された。再試行後も保存先は1件で、1本目の本文は残った。曖昧な枝は確認待ち、保存先欠落は実行不可になった。 |
| M4C_07 | Undo 後に保存先を未保存編集または削除すると Redo は拒否された。保存先の内容・パスを戻すと再適用できた。 |
| M4C_08 | 同名の画像とノートを移動元・先の両フォルダに配置した。Wiki・Markdown の4参照が元のファイルを指すことを Obsidian のメタデータで確認した。CRLF のコードブロックを保持し、既存出力の LF 変更だけでも再利用を拒否した。 |

「切り出し先をマップで開く」、合成 IME イベント中の Enter 抑止、相対 Markdown リンク設定での別フォルダへの遷移も確認した。相対設定の通常出力が上位フォルダ参照になる場合は、マップで開ける Vault 内パスで同じ実ファイルを指定した。

既存の隔離回帰5スイートは M4-b 13件、M4-a 9件、Phase 1 14件、M2-c P1 7件、M2-c 基本6件が通過した。保存確定直後の Escape とキャンセルでタイムアウトした試験は、テスト用コピーで編集欄の終了・ボタンの有効化・フォーカスを待って再実行した。

## 検証の範囲

ファイル書き込み失敗や最終検査直後の競合は意図的な障害注入で確認した。2ファイルを同時に更新する原子性は前提にしていない。元にも外部変更がある場合は「未完了の切り出しを復旧する」で元枝の Markdown を取り出せる。今回の新しいモーダルでの物理日本語 IME、Windows/Linux、スクリーンリーダーの確認は未実施。
